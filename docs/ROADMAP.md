# Roadmap

The outcome is a useful Brazilian-controlled communication network. Transport decisions must serve that outcome. Phases are gated by evidence, not calendar promises.

| Phase                             | Deliverable                                                                                                                                            | Evidence needed to move on                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 0 — current experiment            | Local identity, signed public events, direct pairing, persistent text, history sync, three-peer forwarding; optional Matrix adapter                    | Real browser tests prove exchange, deduplication, reload persistence, and disconnected-write synchronization                      |
| 1 — 5–10 technical testers        | Recoverable identity, clear delivery status, usable invitations, basic blocking and diagnostics, mobile/network testing                                | People can recover access and communicate across the networks they actually use; private-versus-public behavior is understandable |
| 2 — first 50–100-person community | One recurring use case, easy onboarding, reliable offline delivery, room-scoped replication, moderation, support, reviewed private messaging if needed | Users voluntarily return, delivery meets observed needs, and operators can handle failures and abuse                              |
| 3 — images and recorded video     | Content-addressed P2P chunk transfer or explicit operator-controlled media storage, quotas, encrypted private attachments, resumable downloads         | Predictable bandwidth/storage cost, safe retention, usable performance on weak networks                                           |
| 4 — multiple communities          | Discovery, independent bootstrap/relay operators, migration/export, governance, client diversity, published protocol                                   | Communities can change supporting operators without losing identity or access; tested recovery from operator outages              |
| 5 — larger network                | Load testing from measured concurrency/message rates, bounded gossip, storage eviction/archive policies, efficient indexing and spam defenses          | Demonstrated capacity and costs at each increment; no untested million-user promise                                               |
| Separate integration track        | Matrix bridge or client mode, then authorized institutional discovery for MSG Gov                                                                      | Confirmed supported interfaces, access permission, compatible room/federation policy and encryption                               |

For the first adoption pilot, compare a Brazilian-operated Matrix deployment with a hybrid P2P design. Keep one familiar interface and record where each transport helps or harms joining, delivery, recovery, and operating cost. A P2P experiment proves technical behavior; it does not prove adoption.

Before inviting the public, select and publish the distribution license, decide who governs the project, and establish how community rules and operational changes are reviewed. Do not buy a data center before the product and traffic justify one.
